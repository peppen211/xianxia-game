# 專案決策紀錄

## 已確認決策
- 遊戲為個人單人、免費、手機瀏覽器遊玩的自由放置修仙 RPG。
- 使用 HTML/CSS/JavaScript 與 GitHub Pages；開發只在 3.3，穩定版 3.2 不得修改。
- 以《凡人修仙傳》小說原著為主要依據；動畫不需要精細演出。
- 遊戲大部分內容以文字敘述呈現；圖片用於頭像、圖鑑、場景及背景。
- 玩家是獨立主角，韓立保有原著人生線，不由玩家取代。
- 玩家基礎起點比照韓立；掌天瓶仍屬韓立，玩家另有自己的獨立機緣。
- 原著修仙規則盡量完整還原至正篇與《仙界篇》結局；死亡及必要重大遊戲機制可作適度調整。
- 平常自動修煉，離線計算收益；突破達標時通知玩家，由玩家決定何時嘗試。
- 劇情以玩家為主線，原著人物與事件融入世界；大部分劇情以文字呈現。
- 系統操作盡量簡化，但不可為方便而隨意改寫原著規則。
- 使用者主要以手機操作；避免要求使用者重複提供已確認資訊或執行繁瑣操作。

## 待確認設計：八大主線階段解鎖順序（v0.81 討論）
- 錄影中可能混淆的狀態：目前階段標籤將「4/4 節點已解鎖」顯示為「已完成」，但節點解鎖不代表故事已讀完或階段事件已完成。
- 目前故事閱讀入口只檢查本階段第一個節點是否解鎖；階段狀態則按解鎖節點數計算，使用兩套不同語意。
- 建議選定單一規則：下一階段需以前一階段的正式通關條件為門檻；未開放的後續階段可顯示名稱與解鎖條件，但劇情按鈕不可用。節點狀態、故事閱讀狀態與階段通關狀態應分開標示。
- 目前只是建議，尚未套用。待與使用者討論後再決定是否以「前一階段所有遊戲條件達成」作為下一階段解鎖條件。

## 已確認方向：劇情解鎖同步境界與戰鬥地圖（UI v0.82）
- 每階段需同時符合最低修煉境界、指定戰鬥地圖已解鎖、前一階段全部節點條件，以及本階段首節點條件。
- 未開放的後續篇章仍可顯示名稱與具體缺少條件，但不可提前開啟正文。
- 現行境界系統只到化神；第 6–8 階段暫以化神作最低境界並依靈界／仙界地圖里程碑開放，待高境界實作時再升級門檻。
- 不要求玩家必須先讀完前一篇，只要求前一階段的遊戲節點條件達成。
