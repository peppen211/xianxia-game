# 《凡人修仙・自由放置 RPG》遊戲設計總覽 v1

> 狀態：方向已確認；本文是設計規格，不代表功能已實作或測試通過。

## 1. 已確認方向
- 核心體驗：放置與探索並重。
- 世界設定：玩家與韓立共存於原著世界；韓立保有掌天瓶，玩家是獨立主角。
- 規則原則：以《凡人修仙傳》及《凡人修仙之仙界篇》原著還原為優先；不以未查證的通用機率或懲罰代替原著規則。
- 開發策略：評估重新整理新架構，保留既有 HTML 舊檔；目前不鎖定 3.2 或 3.3 為唯一開發基底。
- 體驗形式：手機優先、單人瀏覽器遊玩、文字敘事為主，角色／場景／圖鑑圖片輔助。
- 放置規則：自動修煉與離線收益；達到突破條件時提醒玩家，由玩家決定何時突破。
- 事件規則：事件可依時間、境界、地點、物品、探索結果及先前選擇觸發；關鍵事件提供選項與後續影響。
- 角色起點：凡人、四屬性偽靈根、尚未正式踏入修仙；玩家的獨立機緣尚未定案。

## 2. 核心遊戲循環
1. 自動修煉與累積資源。
2. 查看境界、修煉進度、資源與事件提醒。
3. 玩家選擇突破時機。
4. 探索地點、採集資源、接觸人物、觸發事件或進入秘境。
5. 獲取功法、丹藥、材料、法器與情報，調整修煉／探索策略。
6. 透過存檔與離線收益延續進度。

放置與探索應能並存；兩者是否互斥、探索是否消耗遊戲時間，仍待設計。

## 3. 世界與境界架構草案
- 凡人起始階段
- 人界：練氣、築基、結丹／金丹、元嬰、化神
- 靈界：煉虛、合體、大乘
- 仙界：真仙、金仙、太乙玉仙、大羅、道祖

以上只作為規劃用的境界骨架，尚未逐項完成原著考證。後續需核對各境界層次、突破條件、壽元、天劫、特殊狀態與仙界修煉機制，不得把草案直接視為最終設定。

## 4. 主要系統
- 放置修煉：進度累積、離線收益、突破條件與提醒。
- 探索：地點、人物、資源、事件、秘境、宗門與坊市。
- 事件／主線：條件觸發、敘事、選項、狀態變化、後續解鎖。
- 功法與物品：可查詢的功法、丹藥、材料、法器／寶物與取得來源。
- 戰鬥：敵人能力、境界差距、功法與法器效果、資源消耗、勝敗結果。
- 存檔：版本化資料結構、載入驗證、升級遷移與復原策略。
- 介面：手機優先；保留目前頂部狀態資訊與底部五個導覽入口作為參考，視覺細節另行確認。

## 5. 現況基線
既有兩份 HTML 的靜態檢視顯示，已具備角色建立、簡化修煉、突破、隨機採集、簡化狼戰、localStorage 存檔及最多 12 小時的離線修煉。完整功法、地圖、主線分支、原著人物互動、宗門／秘境、完整物品資料庫與仙界完整系統尚未在這兩份檔案中找到。商店介面存在，但完整買賣流程尚未實作。
- 存檔 key：`mortalCultivationSaveV2`；跨版本相容性尚未驗證。
- 以上是靜態程式檢視，不等同於瀏覽器、手機或部署測試。
- 程式現況詳見 `docs/GAME_IMPLEMENTATION_AUDIT.md`。

## 6. 新架構原則
1. 先保留舊版檔案，不在尚未完成方案前覆寫。
2. 比較單一 HTML 與模組化多檔案架構，再決定原型形式。
3. 以獨立的新原型驗證核心循環，避免直接破壞舊版。
4. 存檔資料需有 schema 版本、載入驗證、遷移與備份／復原策略。
5. 每項工作標記為「已確認規格」「待實作」「已實作」「靜態檢查」「瀏覽器測試」「手機測試」「部署驗證」之一。

## 7. 建議開發順序
1. 完成架構評估與第一個可玩版本範圍。
2. 定義角色、境界、修煉、資源、事件與存檔資料模型。
3. 建立最小可玩切片：建立角色、持續修煉、離線收益、突破提醒／手動突破、存檔載入。
4. 加入一個可探索地點、一種物品與一個條件事件，驗證放置與探索如何共存。
5. 進行手機瀏覽器測試與存檔回歸測試。
6. 再擴充戰鬥、功法、宗門、秘境、主線及高境界內容；境界資料同步逐段原著考證。

## 8. 待討論事項
- 玩家獨立機緣與長期成長差異。
- 第一個可玩版本的精確範圍。
- 單檔或模組化架構，以及舊存檔是否需要匯入新原型。
- 探索與修煉是否同時進行、時間成本及危險／撤退規則。
- 突破失敗、受傷、死亡、壽元與天劫如何按原著分境界處理。
- 主線事件能否被改變、錯過後是否永久關閉、是否允許重玩。
- 背包容量、裝備欄、堆疊、製作、交易與自動使用規則。
- 存檔匯出／匯入、雲端同步、多裝置支援。
- 美術來源與授權、手機驗收標準及正式發布流程。
