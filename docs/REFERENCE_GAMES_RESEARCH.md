## 2. 可以吸收的設計模式

以下是對本專案的建議，不代表參考遊戲已逐項實測，也不是已確認要實作的需求。

### A. 離線修煉回歸摘要
**來源靈感：** 放置／增量遊戲常見的離線追趕與回歸呈現。
- 回到遊戲時摘要離線時長、獲得修為、資源與解鎖事件。
- 若達到突破條件，顯示「已可突破」提醒，但不自動替玩家突破。
- 對長時間離線收益設上限或分段規則，待平衡測試決定。
- 以時間戳結算，不依賴背景計時器逐秒運行。
- 測試頁面重開、背景／前景切換、系統時間倒退、重複結算。
**建議優先級：高。** 與已確認的自動修煉及手動突破方向一致。

### B. 資料驅動的境界、物品與事件
**來源靈感：** 模組化 RPG 與增量遊戲的資料／邏輯分離。
- 境界、功法、物品、地點、事件以穩定 ID 定義。
- 事件以條件、選項、結果、後續事件表達，減少散落在 UI 的硬編碼。
- 原著依據加上來源、章節、考證狀態。
- 規則引擎與顯示文字分開，方便查證與平衡。
**建議優先級：高。** 已在核心資料模型草案中預留欄位。

### C. 存檔版本化、匯出與復原
**來源靈感：** Adventurer's Guild 類瀏覽器遊戲常見的存檔管理模式。
- 新原型使用獨立存檔 key，不與舊 HTML 共享。
- 存檔帶 schema 版本，讀取時驗證欄位。
- 提供 JSON 匯出／匯入前的檔案驗證與錯誤提示。
- 保留上一份有效存檔或提供復原點；錯誤資料不得立即覆寫。
- 匯入舊版存檔列為獨立功能，不假設自動相容。
**建議優先級：高。** 適合在原型早期實作，避免後期資料格式難以遷移。

### D. 探索地點與遭遇資料表
**來源靈感：** RPG 的地圖、遭遇表與資料驅動內容。
- 地點定義解鎖條件、可執行行動、可遇角色、資源和事件。
- 地點內容依境界、物品、已知情報、先前選擇等條件開放。
- 先做一個可探索地點，驗證完整循環，再擴張世界地圖。
**建議優先級：中高。** 與放置並重的方向一致；探索是否消耗時間仍待決定。

### E. 長期成長與階段性目標
**來源靈感：** Progress Knight 與增量遊戲的長線成長。
- 每個境界提供短期目標、可解鎖內容與長期方向。
- 讓資源、功法、探索與突破彼此有用途，避免只有單一數值持續累加。
- 可設計境界階段里程碑與圖鑑／紀錄回饋。
- 不直接套用轉生或重置機制；本遊戲是否需要輪迴玩法尚未決定。
**建議優先級：中。** 有助長期動機，但需服從原著世界觀。

### F. 手機優先的資訊層級
**來源靈感：** 瀏覽器遊戲與文字放置遊戲的簡潔狀態面板。
- 顯示境界、修為進度、靈石、氣血、修煉狀態及待處理提醒。
- 將細節放進可展開頁面，避免小螢幕一次塞滿所有數值。
- 重要操作（突破、消耗珍貴物品、重置）要明確確認。
**建議優先級：中高。** 與現有手機優先介面方向相容。

### G. 戰鬥結果可解釋、可測試
**來源靈感：** RPG 戰鬥系統與可重現的隨機結果測試。
- 將命中、傷害、效果、掉落等規則拆成獨立函式。
- 測試時可固定隨機種子或注入可控亂數，方便重現 bug。
- 戰鬥紀錄解釋關鍵結果，避免只顯示隨機勝敗。
- 不在原著規則未考證前設定通用突破機率或懲罰。
**建議優先級：中。** 先建立可測試規則，再擴充敵人與技能。

## 3. 建議採用的優先順序

| 優先級 | 系統／設計 | 建議階段 | 理由 |
|---|---|---|---|
| P0 | 存檔 schema 版本、載入驗證、時間戳結算 | 新原型基礎 | 直接影響進度安全與離線收益正確性 |
| P0 | 修煉回歸摘要、突破提醒、手動突破 | 第一個可玩切片 | 已確認的核心體驗 |
| P0 | 境界／物品／事件資料與邏輯分離 | 第一個可玩切片 | 為後續原著內容擴充打底 |
| P1 | 一個探索地點＋一個條件事件＋一種資源 | 第一個可玩切片 | 驗證放置與探索並重 |
| P1 | 手機狀態摘要與重要操作確認 | 第一個可玩切片 | 避免小螢幕操作混亂 |
| P2 | 可測試戰鬥規則與戰鬥紀錄 | 後續階段 | 目前戰鬥只是簡化流程 |
| P2 | 圖鑑、里程碑、長期成長目標 | 核心循環穩定後 | 增加長期目標但不擴大首版範圍 |
| 待定 | 轉生、輪迴、重置、離線時間銀行 | 不納入初版 | 不一定符合原著還原與目前方向 |

## 4. 採用前必須做的檢查

1. **實際試玩：** 記錄遊戲流程、操作步數、手機可讀性、離線返回與存檔行為。
2. **原始碼檢查：** 確認實際有無該功能，不只依賴 README。
3. **授權檢查：** 確認 LICENSE、圖片／字體／音效來源及其使用限制。
4. **設計轉譯：** 只吸收抽象設計模式，避免複製其他作品的文案、地圖、數值表或美術。
5. **本專案驗收：** 為採用的每項設計建立可測試的驗收條件。
