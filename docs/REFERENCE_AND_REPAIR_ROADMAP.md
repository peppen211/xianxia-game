# 全修整參考研究與開發路線

更新日期：2026-10-23  
適用範圍：目前 GitHub Pages 實際入口 `index.html`，以及後續經確認的整合版本。  
原則：先穩定、再完善、後擴充；只供個人單機遊玩，不依賴多人連線或遊戲伺服器。

## 參考研究

### 1. 《凡人修仙傳》原作與動畫：世界觀基準
- 韓立開局為凡人，具四屬性偽靈根；修仙成長應由凡人時期逐步展開。
- 修煉體系需區分煉氣期的層數與後續大境界的初、中、後期等階段，不應把所有境界簡化成同一種層數。
- 長春功是韓立早期修煉的關鍵功法，功法更替應與原作進程相符。
- 原作未明確描述的放置收益、日常採集與遊戲數值可以合理設計，但必須標示為遊戲化設計，而不是原作既定設定。

參考：  
- 凡人修仙傳百科〈修煉與境界〉：https://rmji.wiki/zh-hant/faq/cultivation/  
- 巴哈姆特動畫介紹與世界觀整理：https://home.gamer.com.tw/artwork.php?sn=5804400

### 2. Melvor Idle：離線成長與互相連動的技能
可借鏡：
- 放置技能之間應互相支援，避免各系統只是獨立的數值按鈕。
- 離線收益與背包／資源循環需要明確規則。
- 參考不代表照搬其線上、付費或雲端功能；本專案維持本機單機方向。

參考：  
- Melvor Idle 官方介紹：https://www.patreon.com/melvoridle/about?l=en-GB  
- Melvor Idle 官方離線客戶端說明：https://news.melvoridle.com/offline-client-now-available-for-beta-testing-on-steam/

### 3. 手機單機 RPG 的通用體驗目標
不以單一遊戲的畫面為規格，而以可測試的使用體驗為準：
- 單手觸控，避免雙擊縮放、長按文字誤選及點擊回饋延遲。
- 內容區獨立捲動，底部導覽保持可用。
- 主要成長、戰鬥與資源操作提供清楚的成功／失敗提示。
- 關閉遊戲再回來時能看懂離線收益如何計算。

## 開發順序

### A. 穩定與資料保護
1. 檢查目前正式入口、工作分支、部署工作流程與存檔格式。
2. 修復已確認的滿血仍購買回春散扣款問題。
3. 驗證離線收益上限、時間倒退、切換背景、重複結算。
4. 驗證存檔格式錯誤、欄位缺失／型別錯誤及本機儲存失敗時的保護策略。
5. 檢查所有交易、突破、任務與戰鬥結算的重複執行風險。

### B. 核心玩法
1. 修煉與離線成長規則一致。
2. 境界突破條件、消耗與結果一致。
3. 戰鬥與探索具有可驗證的資源／傷害結算。
4. 商店、背包、丹藥、材料、功法及裝備必須真正影響遊戲。
5. 任務可追蹤進度且獎勵只能領取一次。

### C. 手機體驗
1. iPhone 尺寸的自動化瀏覽器測試。
2. 觸控、文字選取、橫向溢出、內容捲動、彈窗與安全區檢查。
3. 可行時安排 iOS Safari 真機驗收；模擬器或 Chromium 通過不等於 Safari 真機通過。

### D. 自動化開發與發布
- PR 上自動執行相關測試。
- 測試失敗時保留錯誤資訊，修復後重跑相同測試。
- 將單機遊戲入口的瀏覽器測試與 React/Vite 原型的單元測試／建置分開記錄，避免把測到不同程式的結果混為一談。
- 不直接發布未驗證的版本；不在未確認前變更 repository 可見度或關閉現有公開入口。
