# 架構決策紀錄 ADR-001：新原型技術結構

- 狀態：建議採用，待以實際原型驗證
- 日期：2026-10-23

## 背景
既有遊戲是內嵌 CSS／JavaScript 的單頁 HTML。未來預期有境界、功法、物品、事件、探索、戰鬥、存檔與原著考證資料，若所有規則持續放在同一檔案，維護與測試成本會提高。另一方面，遊戲需能以靜態網站方式部署並支援手機瀏覽器。

## 決策提案
- 新原型採 TypeScript 模組化原始碼。
- 使用輕量建置工具輸出可由 GitHub Pages 靜態託管的成品。
- 遊戲規則與資料、存檔邏輯、UI 分離。
- 初期不引入伺服器、帳號或雲端資料庫。
- 舊 HTML 原封保留作為歷史版本與行為參考。
- 新原型使用獨立存檔 key，不直接共用舊版資料。

## 候選方案比較
| 方案 | 優點 | 風險／成本 | 結論 |
|---|---|---|---|
| 繼續單一 HTML | 最簡單，直接部署 | 系統擴張後難測試，資料與 UI 容易糾纏 | 可保留作歷史版，不建議作長期新基底 |
| 原生 JS 多模組 | 依賴少，瀏覽器原生支援 | 型別約束與資料結構檢查較弱；本機測試需 HTTP server | 可作極簡方案 |
| TypeScript + Vite | 型別檢查、模組化、靜態建置成熟 | 需維護建置設定，需確保 Pages 路徑設定正確 | 建議先用此方案驗證 |
| React／大型 UI 框架 | 複雜 UI 與狀態元件生態豐富 | 首版可能增加不必要的依賴與抽象 | 不先採用，除非原型證明有必要 |

## 初步目錄
- `src/core/`: 時間、遊戲狀態與規則共用型別
- `src/systems/cultivation/`: 修煉與突破
- `src/systems/exploration/`: 地點與探索事件
- `src/data/`: 境界、物品、地點、事件資料
- `src/save/`: 存檔 schema、驗證、讀寫
- `src/ui/`: 手機優先畫面與操作
- `tests/`: 核心規則與存檔測試
- `dist/`: 建置輸出，不手動編輯
- 舊 HTML 保留在既有位置，不在本階段移動或刪除

## 風險與緩解
- GitHub Pages 子路徑：設定正確的 base path，部署後實際點擊驗證。
- 離線時間重複結算：統一時間結算入口並為背景切換、重開建立測試。
- 存檔破壞：版本化 schema、載入驗證、保留無效原始資料。
- 原著資料錯誤：靜態資料加入考證狀態與來源，不把草案當正式規則。
- 手機相容性：真實手機瀏覽器測試與桌面測試分開記錄。

## 下一步驗證
1. 建立最小 TypeScript + Vite 專案骨架。
2. 先實作純函式時間結算與存檔 schema。
3. 建立單元測試。
4. 在本機／CI 建置並驗證 GitHub Pages 靜態輸出。
5. 通過後才逐步增加 UI 與探索切片。
