# 第一個可玩切片：驗收標準 v1

> 狀態：本階段可執行規格。規格建立不代表功能已實作或測試通過。
> 目標：以最小範圍驗證「放置修煉 + 手動突破 + 一個探索地點 + 條件事件 + 安全存檔」。

## 1. 範圍

### 必須完成
- 新原型獨立於舊版 HTML；不得共用舊存檔 key。
- 建立角色：名稱、四屬性偽靈根、初始境界／狀態。
- 顯示角色狀態、修為進度、基本資源及修煉狀態。
- 自動修煉與時間戳結算；離線返回顯示收益摘要。
- 達到規則條件時提示可嘗試突破；不自動替玩家突破。
- 一個探索地點、一項可取得資源、一個有條件的文字事件。
- 存檔、讀檔、schema 版本、基本驗證與安全失敗處理。
- 手機窄螢幕可操作，重要操作有清楚回饋。

### 不在本階段
- 完整原著主線、全部境界與仙界內容。
- 完整宗門、秘境、坊市、製作與交易。
- 複雜戰鬥、雲端帳號、多裝置同步。
- 直接覆寫舊 HTML 或自動匯入舊版存檔。

## 2. 驗收測試

### 角色與基本狀態
- 新玩家能建立角色並看到名稱、靈根、境界與修為。
- 重新整理後角色狀態仍存在。
- 無效或缺漏資料不會令整個介面白屏。

### 修煉與時間
- 修煉進度由統一時間結算函式更新。
- 頁面背景／前景切換不重複結算同一段時間。
- 關閉再開後，離線收益依時間差結算一次。
- 時間差小於零時，不產生負修為、負資源或反向回退狀態。
- 過長離線時間的上限必須明確，不能隱藏地重複領取。
- 回歸摘要只顯示實際結算的收益。

### 突破
- 未達規則條件時，突破操作不可執行。
- 達標時顯示可嘗試提示，但玩家必須主動選擇。
- 成功／失敗結果由獨立規則函式決定，可單元測試。
- 規則尚未完成原著考證的部分需標記為原型暫定規則，不宣稱原著還原。

### 探索與事件
- 地點依條件開放；探索結果可改變資源或事件旗標。
- 條件未成立時事件不觸發。
- 同一個一次性事件的效果不能重複套用。
- 重新載入後，已觸發狀態與獲得資源保持一致。

### 存檔
- 新原型使用獨立 storage key。
- 存檔帶 schemaVersion 與 savedAt。
- 無效 JSON、未知 ID 或欄位缺漏時有安全處理，不直接覆寫有效存檔。
- 儲存／載入後關鍵欄位一致。
- 匯入／匯出不是本階段必需功能，但資料格式應預留演進空間。

### 手機與瀏覽器
- 窄螢幕下主要按鈕可見且可點擊，不需橫向捲動才能操作核心循環。
- 測試重新整理、切換背景、鎖屏後返回、關閉再開。
- 至少在桌面 Chromium 與手機 Safari 或等效真實 iOS 瀏覽器執行核心流程。
- 若未能取得真實 iOS 測試，明確標記為未測，不以桌面模擬代替。

## 3. 測試紀錄格式
每個案例記錄：
- ID、測試日期、環境／瀏覽器
- 前置狀態、操作步驟、預期結果、實際結果
- Pass／Fail／Blocked
- 證據或錯誤描述、修正提交
- 未執行項目不得標記 Pass

## 4. 完成定義
只有在必需案例全部 Pass，且手機主要操作與存檔／離線計算沒有已知阻斷問題後，才能標記此切片完成。規格完成、程式完成、測試完成、部署完成須分開記錄。
